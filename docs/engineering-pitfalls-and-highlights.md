# 工程问题与验证结论

这份公开清单只保留已经定位、已经处理并有防回归证据的案例。完整过程日志保存在本机 `.local-docs/engineering/`，不作为当前状态来源。

## 1. 流式工具调用不能按 chunk 直接解析

**问题**：模型会把同一个工具调用的名称和 JSON 参数拆到多个流片段中，直接逐片解析会产生非法参数或重复执行。

**处理**：按 tool-call id 累积片段，轮次结束后统一校验；工具可以并发执行，但结果按模型请求顺序回填。

**证据**：`loop/core` 的轮次驱动与工具执行测试覆盖分片、非法 JSON、并发和顺序语义。

## 2. 暂停不能依赖“原线程还活着”

**问题**：人工审批可能跨刷新、跨进程甚至跨部署，阻塞线程无法提供可靠恢复语义。

**处理**：将待审批请求、原参数、能力变体和归属写入 `agent_pause_state`；批准后从持久化快照恢复，并保护重复提交。

**证据**：`AgentApprovalHttpIT`、PauseState 与 Runtime Adapter 测试覆盖归属、恢复和重复批准。

## 3. 历史回放不能带回旧工具 timeline

**问题**：跨模式会话如果把旧轮次 `tool_call_id` 重新发送给另一个执行器，模型上下文会出现无法配对的工具消息。

**处理**：长期会话历史只回放问题和最终回答；timeline 用于 UI 和审计，不重新进入模型消息列表。

**证据**：`AgentLoopExecutorHistoryMessageTest` 固化该契约。

## 4. SQL 权限不能靠字符串拼接

**问题**：字符串拼接容易被 `OR` 优先级、别名、JOIN 位置和子查询绕过；正则也无法可靠理解 SQL 结构。

**处理**：`SqlSafetyGuard` 先做只读语法检查，`DataScopeRewriter` 在 AST 上注入数据范围，`SensitiveFilter` 根据真实来源列脱敏。

**证据**：相关单元测试与 Testcontainers MySQL 集成测试覆盖别名、JOIN、子查询和失败关闭。

## 5. 文件绑定必须与轮次提交处于同一事务

**问题**：先提交对话再绑定附件会留下半完成状态；失败后依赖后台 sweep 自愈会让语义不确定。

**处理**：由 `TurnCommitter` 在同一事务中完成轮次落库和显式 `fileIds` 绑定，并校验文件仍属于当前用户和会话。

**证据**：`TransactionalTurnCommitterIT` 在真实 MySQL 上验证成功和回滚路径。

## 6. Prompt 需要版本和漂移检测

**问题**：散落在 Java 常量里的提示词无法统一审查，也无法解释某次结果使用了哪个版本。

**处理**：主要提示词由 `PromptRegistry` 从资源目录加载，版本锁检测正文漂移，trace 记录非空 prompt stamp。少量一次性多模态指令作为明确例外留在调用类中。

**证据**：`PromptRegistryLockTest` 和 prompt stamp 相关测试。

## 7. PPT 的“成功”必须由产物验证决定

**问题**：Python 进程返回 0 不代表 PPT 可用；截断正文还可能留下半条项目符号或让文本越出模板框。

**处理**：状态机分离业务 checkpoint 与运行状态；渲染后重新打开 OOXML，校验页数和文件大小；富模板正文按完整段落截断并启用文字适配。

**证据**：`PptVerifier`、`RenderStrategyRichTemplateTest` 及恢复/幂等测试。

## 8. 依赖审计必须和构建、测试一起验证

**问题**：只执行自动强制升级可能跨主版本破坏工具链；只修直接依赖又可能保留易受攻击的传递版本。

**处理**：在兼容范围内升级 Vite，升级到已修复公告的 Vitest 版本，重新生成锁文件，并同时运行 `npm audit`、92 项前端测试和生产构建。

**结果**：当前 npm 审计为 0 漏洞。
