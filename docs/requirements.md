# AgentTrail 需求与边界

> 状态：当前文档。最近核对：2026-08-27。

## 1. 产品目标

AgentTrail 提供一套可扩展的 Agent Runtime，使模型驱动任务具备稳定的工具执行、上下文管理、状态恢复、安全治理和评测能力。业务能力以 Capability Pack 形式接入，不应复制 Runtime 的通用机制。

目标优先级：

1. 端到端链路真实可运行；
2. 权限、恢复和失败行为可预测；
3. 关键机制有自动化测试和观测证据；
4. 新能力尽量通过扩展点接入，而不是修改核心循环。

## 3. 功能要求

### 3.1 Runtime

- 一轮推理由模型流、工具调用与工具结果组成；达到最大轮次时必须可控收尾。
- 工具参数由 Schema 校验，身份、文件和权限参数必须由服务端注入，不能信任模型输入。
- 会话历史、暂停状态和审计记录必须持久化；跨实例能力启用时使用 Redis 协调。
- 模型调用、工具调用和内部结构化调用必须有明确超时和错误分类。

### 3.2 数据分析

- SQL 只允许只读语句，并在执行前通过 AST 校验。
- 数据范围必须通过 AST 注入，不能用字符串拼接或依赖模型自觉。
- 脱敏按真实来源列判断，别名不得绕过。
- 图表只能消费工具产出的数据，不允许根据模型编造的数据生成。

### 3.3 文件、研究与 PPT

- 文件必须显式绑定到用户、会话和轮次；失败事务不能留下半绑定状态。
- 深度研究和 PPT 必须提交即返回任务标识，并提供状态、取消和历史恢复入口。
- PPT 只有在主题、页数、受众和风格满足最低要求后才创建任务。
- PPT 成功态必须以可重新打开的有效 OOXML 产物为前提。

## 4. 非功能要求

| 维度 | 要求 |
|---|---|
| 安全 | 默认拒绝越权访问；凭据只从本地配置或 Secret 注入；日志不得输出签名 URL 和敏感值 |
| 一致性 | 状态变更与业务记录采用事务或幂等键保护；重复请求不得重复创建副作用 |
| 可观测性 | 暴露健康检查、Prometheus 指标、OTel trace 和可验证审计记录 |
| 测试 | 单元测试覆盖纯逻辑；MySQL/Redis 语义使用 Testcontainers；前端必须通过测试与生产构建 |
| 可维护性 | 当前事实只维护在本文件、架构文档和代码；日期快照不得充当活文档 |

## 5. 已知边界

- DeepResearch 已持久化任务元数据和终态，但尚未做到 PPT 同等粒度的阶段 checkpoint 续跑。
- Flyway 已接入但默认关闭，本地仍以 `db/schema.sql` 初始化；迁移事实源尚未完全收敛。
- PgVector、MinIO、Redis、MCP 和联网搜索属于可选外部依赖；未配置时相关能力需要明确降级。
- 当前提供本地/Compose 运行方式，没有把 Kubernetes、容量基线和多区域部署作为已完成能力。
- 通用多 Agent 路由和 A2A 协议不是当前交付范围；只有出现真实业务场景时才引入。

## 6. 验证入口

```powershell
mvn test
cd frontend
npm.cmd test
npm.cmd run build
npm.cmd audit
```

涉及 SQL 权限改写、SQL 安全或脱敏时，还需运行 Golden 门禁：

```powershell
mvn verify -Pgolden
```
