# 可观测性、验收、测试与增量交付

> 上级文档：[PPT 生成能力重构需求文档](../ppt-generation-refactor-requirements.md)
> 需求范围：R42–R43、E1–E15

## 1. R42：指标

至少提供：

- 各阶段成功率与耗时分位数；
- 各模型调用 token 和费用；
- 各阶段重试次数；
- 等待输入时长；
- 取消响应时长；
- 渲染队列长度、运行数、超时数；
- 模板选择分布；
- VERIFY 失败原因；
- 降级成功率；
- 任务端到端成功率。

指标标签必须控制基数，不得直接把 taskId、conversationId、完整错误信息作为指标标签。

## 2. R43：日志与追踪

- 日志携带 taskId、conversationId、stage、attempt、workerId；
- 不记录凭证、签名 URL 和完整敏感内容；
- Java 调用、外部工具、图片生成、Python 渲染和对象上传串联到同一任务；
- 每次 checkpoint 提交记录 revision 与前后状态；
- 错误码、warning code 与阶段事件保持一致；
- 用户可见 message 与内部 exception 分开记录。

## 3. 端到端验收场景

### E1：正常创建

用户发起明确需求，前端立即显示任务卡片；任务依次推进并生成可下载 PPT；刷新页面后仍显示成功和下载按钮。

### E2：需求澄清

需求不明确时进入 WAITING_INPUT；用户在卡片提交补充；任务从 REQUIREMENT 继续；刷新后不重复追问。

### E3：模型输出异常

SCHEMA 首次解析失败且判定可重试；自动重试成功；已完成阶段不重跑；阶段事件能看到两次 attempt。

### E4：人工恢复

自动重试耗尽后进入 FAILED；前端显示失败阶段和继续按钮；点击继续后从失败阶段恢复并成功。

### E5：页面关闭

任务运行中关闭页面；后端继续；重新进入会话后通过 taskId 获取最新状态并恢复轮询或下载。

### E6：服务重启

任务停在 OUTLINE、IMAGE、RENDER 三种阶段时分别重启服务；租约过期后正确恢复；同一阶段不会由两个 worker 同时提交。

### E7：取消

分别在检索、图片生成和 Python 渲染期间取消；前端进入取消中；执行单元停止；最终为 CANCELLED；不产生 SUCCESS checkpoint。

### E8：多实例下载

实例 A 生成任务，实例 B 接收下载请求；通过对象存储成功下载，不依赖实例 A 本地磁盘。

### E9：降级成功

图片服务不可用时生成无图或装饰图版本；任务成功且带 warning；前端不显示为失败。

### E10：模板损坏

模板缺少必填 shape 或关系损坏；模板在注册或启动校验时被禁用，不进入用户可选列表。

### E11：渲染缺字段

渲染时必填 shape 未填充；VERIFY 拒绝 SUCCESS，并提供稳定错误码。

### E12：局部修改

用户要求修改第 3 页标题；新任务引用旧版本；只改变目标页和受影响素材；旧版本仍可下载。

### E13：创建请求重放

同一幂等键重复提交三次，只创建并执行一个任务，三次都返回同一 taskId。

### E14：历史状态不漂移

任务首次失败后恢复成功；刷新页面后历史卡片显示成功，不回退到首次失败。

### E15：越权访问

用户 A 无法查询、恢复、取消、修改或下载用户 B 的任务和产物。

## 4. 测试要求

### 4.1 后端单元测试

- 状态与生命周期组合；
- checkpoint 提交时序；
- contextVersion 迁移；
- revision 冲突；
- 错误分类和重试预算；
- 取消状态转换；
- 模板选择和 Schema 验证；
- 修改 patch；
- capability flags；
- 会话 task 引用解析。

### 4.2 集成测试

- 使用真实数据库验证 checkpoint、乐观锁、租约和启动恢复；
- 使用真实对象存储或兼容容器验证上传、下载、签名和归属；
- 使用真实 Python 子进程验证超时、取消、非零退出和产物校验；
- 使用包含图片、背景、组合元素的模板验证关系复制；
- 验证最终 PPT 能重新打开并读取关键字段；
- 验证 worker 多实例竞争只有一个提交成功。

### 4.3 前端测试

- 每种 runStatus 的卡片展示和按钮；
- 创建后轮询；
- 澄清提交；
- 重试与取消；
- 网络失败恢复；
- 历史任务批量刷新；
- 路由切换和重新进入；
- 多版本下载；
- warning 与 failure 区分；
- 越权和产物不存在提示。

### 4.4 端到端测试

E1–E15 均形成可重复执行的端到端用例。安全与任务一致性场景作为合入门禁；依赖真实模型的内容质量场景作为质量诊断，不作为完全确定性的硬门禁。

## 5. 迁移与兼容

1. 保留现有 HTTP 路径，先扩展响应字段，前端切换后再评估版本升级。
2. 为现有任务快照定义 legacy contextVersion，并提供读取迁移。
3. 将旧 `status + error_msg` 映射到新的 pipelineState + runStatus。
4. 旧任务本机 outputPath 在迁移窗口内继续支持下载，后台逐步上传并补 artifactId。
5. 旧 templatePath 映射到默认 templateId/version。
6. 会话历史旧 PPT payload 读取 taskId 后回查；缺少 taskId 的旧失败记录只读展示。
7. 新旧前端并存期间，后端不得移除旧字段。
8. 每个迁移阶段可回滚，不能要求一次性清空任务表。

## 6. 增量交付与小提交计划

每个提交都必须保持系统可编译、可测试且旧功能可用。

1. 为任务响应增加 pipelineState/runStatus 只读映射，不改变执行逻辑。
2. 增加 contextVersion，并为旧快照提供默认版本读取。
3. 增加 revision 字段和持久化映射，暂不启用冲突校验。
4. 状态推进改为 expected state + revision 条件更新。
5. 增加阶段事件表和成功阶段事件写入。
6. 增加失败、取消和降级阶段事件。
7. 定义结构化错误对象，保留旧 errorMsg 兼容字段。
8. 接入失败分类器但暂不自动重试。
9. 增加阶段 attempt 和有限自动重试。
10. 将幂等键从进程内存迁移到持久化存储。
11. 会话 StageOutput 改为稳定 task 引用，并兼容旧 payload。
12. 历史加载后批量回查任务状态。
13. 前端任务卡片切换为统一任务视图和 capability flags。
14. 前端增加取消调用和取消中状态。
15. 后端将取消信号接入 worker/Future。
16. Python 渲染进程支持显式终止和子进程清理。
17. 增加启动恢复扫描和有界重新入队。
18. 最终 PPT 上传对象存储，下载兼容 artifact 与旧本机路径。
19. 成功任务本地临时目录按策略清理。
20. 引入模板注册表和默认模板迁移。
21. 增加模板离线/启动校验，先覆盖当前默认模板。
22. 增加视觉规划模型和状态，默认输出与旧模板兼容。
23. 将固定 Schema 升级为带 pageId/pageType 的兼容结构。
24. 增加 CATALOG、COMPARE、END 页面类型。
25. 增加 image/background/chart 字段和素材任务模型。
26. 内容页配图从装饰图扩展为逐页语义素材，保留降级。
27. Python 复制补全关系、背景和媒体，并增加复杂模板测试。
28. 增加 VERIFY 阶段结构检查。
29. 增加可选预览图与视觉检查。
30. MODIFY 改为基于旧 Schema 的 page patch。
31. 前端增加版本关系和历史产物下载。
32. 删除已过兼容期的旧状态推导和旧 payload 分支。

## 7. 需求追踪与合入门禁

每个实现 PR/提交应标注：

- 覆盖的 R 编号；
- 对应的 E 编号或新增测试；
- 数据迁移与回滚方式；
- 前端、后端是否需要同步上线；
- 兼容路径何时删除。

涉及统一任务视图、状态语义或会话引用的变更，前后端测试必须在同一交付批次通过。涉及 checkpoint、租约、对象存储与鉴权的变更必须有真实基础设施集成测试。

## 8. 完成门禁

- E1–E15 全部有自动化或可重复脚本；
- 后端单元与真实基础设施集成测试通过；
- 前端状态矩阵、历史恢复和版本下载测试通过；
- 新旧数据迁移与回滚演练通过；
- 关键指标、日志与阶段事件能定位失败；
- 总入口文档中的完成定义全部满足。
