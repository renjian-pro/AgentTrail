# AgentTrail 路线图

> 状态：当前文档。最近核对：2026-08-27。这里不重复已经关闭的施工票，只记录能力基线和仍可能继续推进的工作。

## 已完成基线

| 阶段 | 交付结果 |
|---|---|
| Runtime | 流式 ReAct loop、同步门面、上下文压缩、工具发现、Skill、记忆、trace、结构化输出 |
| 分布式与恢复 | Redis 单飞锁和广播停止、HITL 持久化暂停恢复、工具幂等 |
| 文件与外部工具 | Tika、PgVector RAG、多模态图片问答、联网搜索、MCP 图表、MinIO |
| 身份与数据分析 | 登录/RBAC、数据范围、Schema、术语、SQL AST 安全、执行、脱敏、计算与图表 |
| 治理与评测 | 风险审批、预算、限速、PII、Prompt Injection、审计哈希链、指标、Golden Case |
| DeepResearch | 澄清、计划、并行检索、批判、总结、取消、终态持久化和会话恢复 |
| PPT | 会话式需求预检、持久化状态机、恢复、模板与素材契约、渲染验证、版本化修改 |
| 前端 | Vue 统一入口、四模式、任务卡片、历史恢复、管理与评测页面 |

## 候选后续工作

这些事项尚未排期，也不代表已经承诺交付。

### P1：状态与迁移收敛

- DeepResearch 增加阶段 checkpoint 与可重放事件，使重启后的行为达到 PPT 同等可解释程度。
- 选择 `db/schema.sql` 或 Flyway 作为唯一迁移事实源，消除双写。
- 对 PPT/图表对象访问策略做一次部署级验证，确保生产环境采用私有对象或受控代理下载。

### P1：质量基线

- 固化关键 Golden 场景的持续回归和报告生成。
- 建立并发、TTFT、任务队列、RAG 和 PPT 渲染的容量基线。
- 给视觉产物增加稳定的版式回归策略，减少只验证“文件可打开”的盲区。

### P2：部署与运营

- 补充 Kubernetes manifests、滚动升级与故障演练。
- 明确外部依赖降级矩阵和生产告警阈值。
- 将运行时配置与 Secret 管理接入实际部署平台。

### 条件触发：多 Agent

只有出现单个 Runtime Profile 无法清晰承载的真实业务协作场景时，才引入 Agent Registry、路由或 A2A。不会为了展示概念提前增加通用编排层。

## 完成定义

一项工作只有同时满足以下条件才从路线图移出：

1. 生产路径已经接线，而不只是存在接口或示例类；
2. 正常、失败、权限和恢复路径有对应测试；
3. 配置、架构和公开文档同步更新；
4. 不再保留与当前代码冲突的“待实现”描述。
